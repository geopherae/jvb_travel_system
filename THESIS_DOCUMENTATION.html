1. System Overview

1.1 Purpose and Mission

The Itinerary and Document Management System for JV-B Travel and Tours is a comprehensive web-based platform designed to streamline travel itinerary management and document processing for a dynamic travel agency. The system serves as a central hub connecting travel agents (administrators) with travel clients, automating the entire journey from initial booking through post-travel feedback.

1.2 Core Objectives

  • Automate Client Onboarding: Streamline the multi-step process from document submission through trip completion
  • Centralize Documentation: Manage passport uploads, ID verification, travel documents, and photo galleries in one secure location
  • Facilitate Real-Time Communication: Enable direct messaging between travel agents and clients for coordination and support
  • Maintain Itinerary Management: Create, customize, and confirm travel itineraries with day-by-day activities and timelines
  • Track Client Progress: Monitor onboarding completion through a structured checklist system with dependencies
  • Provide Comprehensive Analytics: Deliver key performance indicators (KPIs) including client conversion rates, document approval times, and onboarding velocity
  • Ensure Audit Compliance: Maintain complete audit trails with actor context, change history, and business impact tracking for accountability
System Vision: Empower travel agencies with intelligent automation while delivering transparent, user-centric experiences that build client trust and accelerate the journey to trip completion.

2.2 Operational Support for JV-B Travel & Tours

A. Client Onboarding Automation

The system replaces manual spreadsheet-based tracking with an automated, step-based onboarding process. When an agent adds a new client, the system:

  • Generates a unique access code (e.g., JVBT-1234) for secure client login
  • Initializes a personalized onboarding checklist with dependencies (e.g., "Confirm Itinerary" only unlocks after ID approval)
  • Automatically updates client status based on document submissions and approvals
  • Sends real-time notifications to both agent and client on status changes

B. Document Management Workflow

Eliminates manual email-based document exchanges:

  • Client Uploads: Clients submit documents (passport, ID, visas) directly through the dashboard
  • Agent Review: Agents preview documents in-app, approve or request resubmission with feedback
  • Automatic Compression: Images are automatically compressed and converted to JPG for storage efficiency
  • Approval Tracking: Timestamps and approving agent names recorded for compliance
  • Change Notifications: Clients are instantly notified of approvals or rejections

C. Itinerary Management & Confirmation

Agents design detailed itineraries with day-by-day activities; clients view and confirm before travel:

  • Agents create packages with origin/destination airports, duration, and daily activity breakdowns
  • Clients view personalized itineraries assigned to their booking
  • Confirmation triggers automated status progression and notification to agent
  • Prevents departure surprises by ensuring pre-trip alignment

D. Real-Time Client-Agent Communication

Reduces reliance on emails and phone calls for coordination:

  • WebSocket-based messaging for instant communication with browser fallback
  • Message history maintained in database for reference and audit
  • Support for thread-based conversations grouped by client-agent pair
  • Read/unread tracking and notification bells for new messages

E. Trip Photo Documentation & Feedback

Post-trip photo sharing integrated into the platform:

  • Clients upload day-by-day photos from their trip (up to 6 per day)
  • Agents review and approve photos before gallery publication
  • Photos tagged by location and scope for organization
  • Automatic compression preserves storage while maintaining quality

F. Notification & Alert System

Keeps all stakeholders informed automatically:

  • Document-related events (upload, approval, rejection) trigger notifications
  • Status changes alert clients and agents simultaneously
  • Message received alerts with inline preview
  • Notifications include action URLs for one-click navigation
  • Clients can dismiss individual or bulk notifications

G. Comprehensive Analytics & Reporting

Provides business intelligence for performance optimization:

  • KPI Dashboard: Total clients, confirmed bookings, completed trips, conversion rates at a glance
  • Document Status Charts: Pie charts showing pending/approved/rejected document distribution
  • Onboarding Velocity: Average time from client creation to first document upload
  • Approval Time Metrics: Average duration from upload to approval per document type
  • Audit Log Export: Searchable, filterable logs of all system actions for compliance audits

H. Multi-Role Administration

Supports organizational hierarchy with role-based access:

  • Superadmin: Full system access, manages other admins and all clients
  • Admin: Manages assigned/unassigned clients, approves documents, sends messages
  • Read-Only: Views clients and documents but cannot approve or modify
  • Configurable session timeouts per admin for security

3. Technology Acceptance Model (TAM) Framework & Data Gathering

3.1 TAM Overview

The Technology Acceptance Model (TAM) is a theoretical framework that explains how users come to accept and use technology. It posits that two factors drive adoption: Perceived Usefulness (PU) and Perceived Ease of Use (PEOU). Both influence users' attitude toward the technology and, consequently, their intention to use it.

TAM Formula:
Behavioral Intention = f(PU, PEOU)
Actual System Usage = f(Behavioral Intention)

3.2 System Design Aligned with TAM Constructs

A. Perceived Usefulness (PU)

Users believe the system improves their job performance and saves time:

  • For Travel Agents (Admins):
    • Centralized client database eliminates spreadsheet hunting
    • Automated status updates reduce manual status-checking overhead
    • Real-time document approvals replace email back-and-forth
    • Comprehensive analytics provide actionable business insights
    • Audit trails provide full compliance documentation
  • For Clients:
    • Single portal for all trip-related activities (documents, itinerary, photos, messaging)
    • Real-time status updates eliminate guesswork about booking progress
    • Direct messaging with agent reduces communication friction
    • Organized document tracking ensures nothing is forgotten

B. Perceived Ease of Use (PEOU)

Users find the system intuitive and require minimal training:

  • Intuitive Navigation: Clear sidebar menus, consistent button placement, logical workflow progression
  • Responsive Design: Works seamlessly on desktop, tablet, and mobile devices
  • Visual Feedback: Status badges, progress bars, and color-coded alerts provide clarity
  • Minimal Onboarding: Clients receive simple access code login; agents get straightforward dashboard
  • Error Prevention: Form validation, confirmation modals, and inline help text reduce mistakes

3.3 In-App Survey Integration for TAM Data Collection

The system embeds TAM constructs directly into user experience surveys, providing rich quantitative and qualitative data:

A. First-Login Survey (Client)

Triggered on client's first session to capture baseline perceptions:

  • Perceived Usefulness Questions:
    • "How useful do you find this system for managing your travel booking?"
    • "To what extent does this system help you stay organized?"
    • Response scale: 1 (Strongly Disagree) to 5 (Strongly Agree)
  • Perceived Ease of Use Questions:
    • "Is the system easy to navigate?"
    • "Do the interface and buttons make sense to you?"
    • Response scale: Same 1-5 Likert scale
  • Task Simplicity: "How easy was it to upload your first document?" Validates PEOU in action
  • Feature Interest: "Which features are most important to you?" Identifies high-impact functionalities

B. Trip Completion Survey (Client)

Administered post-trip to measure perceived impact and satisfaction:

  • Behavioral Intention: "Would you recommend this travel agency to a friend based on this experience?"
  • Ease of Use Validation: "Did you have difficulty accessing your trip information during travel?"
  • Usefulness Validation: "Did real-time messaging with your agent improve your travel experience?"
  • Overall Satisfaction: Net Promoter Score (NPS) question: "On a scale of 0-10, how likely are you to recommend this service?"

C. Weekly Admin Survey

Scheduled survey for administrators measuring workflow efficiency:

  • PU for Admins: "How much has this system improved your ability to manage clients?"
  • PEOU for Admins: "How easy is it to approve documents and update client status?"
  • Behavioral Intention: "Are you satisfied with the system's features and stability?"
  • Data collection frequency: Weekly automated surveys for trend analysis

3.4 Logging & Auditing for TAM Study Support

Beyond surveys, the system's comprehensive logging capability provides objective evidence of technology acceptance through behavioral data:

A. System Action Audit Log

Every user interaction is logged with complete context:

Field Purpose for TAM Study

actor_id, actor_role Compare usage patterns between admins and clients, identify super-users vs. light users
timestamp, session_id Calculate session duration, feature adoption timeline, and usage frequency trends

severity, module, business_impact Prioritize high-impact features; measure value delivered by each system component
ip_address, user_agent Analyze device types and access patterns (mobile vs. desktop adoption)

B. KPI Metrics for Behavioral Evidence

Objective metrics that validate TAM's behavioral intention → usage relationship:

  • Adoption Velocity: Time from client creation to first login → measures perceived usefulness (clients must see value to return)
  • Onboarding Completion Rate: % of clients reaching "Confirmed" status → behavioral intention outcome
  • Document Submission Rate: Clients who upload ≥1 document vs. total clients → PEOU validation (easy to use = higher submission)
  • Average Session Duration: Time spent in system per session → engagement metric linked to PU
  • Feature Adoption Rate: % of admins using messaging, % uploading photos, etc. → which features drive actual usage
  • Support Ticket Volume: Lower support needs = higher PEOU (system is intuitive)
  • Client-Agent Message Frequency: Higher messaging = lower perception that system reduces communication friction

C. Error Log Analysis

Identifies usability friction points:

  • Form validation errors indicate unclear input requirements (PEOU issue)
  • Failed file uploads point to confusing upload UI
  • High "back" button usage suggests confusing navigation
  • Repeated failed login attempts indicate authentication confusion

3.6 TAM Hypotheses Testable with This System

  • H1: Higher perceived usefulness scores correlate with longer session durations and higher feature adoption
  • H2: Higher perceived ease-of-use scores correlate with faster document submission and fewer support requests
  • H3: Users who complete surveys with high PU/PEOU show higher onboarding completion rates
  • H4: Mobile users report lower PEOU than desktop users; system adoption rates reflect this gap
  • H5: Real-time notification features increase perceived usefulness and reduce perceived communication effort
  • H6: Automated status updates reduce perceived cognitive load (PEOU) compared to manual checking

4. System Architecture

4.1 High-Level Architecture Diagram

The system follows a three-tier architecture with data persistence:

Architecture Overview

The diagram illustrates a three-tier web application architecture built with procedural PHP 8.2+, MySQL 10.4+ (with JSON support), and responsive frontend using Tailwind CSS and vanilla JavaScript. The system comprises three interconnected layers—Client Layer, Admin Layer, and Processing Layer—all interfacing with a centralized Database Layer containing 18 core tables.

Client Layer (User-Facing Portal)

Travel clients authenticate using a unique access code (e.g., JVBT-1234) generated upon booking. The personalized dashboard enables clients to:

  • View & Confirm Itineraries: Detailed day-by-day activities with trip dates; confirmation triggers automated status progression.
  • Upload & Track Documents: Submit travel documents (passports, IDs, visas) with real-time approval status tracking (Pending/Approved/Rejected); automatic compression and validation applied.
  • Real-Time Communication: Direct messaging with assigned agents via WebSocket; upload post-trip photos; receive in-app notifications for approvals and updates.
  • Complete TAM Surveys: First-login and post-trip surveys to assess system usefulness and ease of use for research purposes.

Processing Layer (Backend Logic Engine)

The processing layer executes business logic through 60+ action handler files, managing:

  • Authentication & Session Management: Centralized guard() function with role-based access control (Superadmin/Admin/Read-Only/Client) and dynamic session timeouts.
  • Document Processing: MIME validation, automatic JPG compression, and secure storage with unique naming (client_{timestamp}_{random}.jpg).
  • Status Auto-Updates & Notifications: Evaluates client progress to automatically advance status (Awaiting Docs → Confirmed → Trip Completed); event-driven notifications broadcast via WebSocket.
  • Comprehensive Audit Logging: Every action logged with actor context (ID, role, IP, session), change history as JSON, and severity classification.

Admin Layer (Agent Management Portal)

Authorized JVB staff authenticate via username/password with role-specific permissions. Key capabilities include:

  • Client & Package Management: Create clients with unique access codes; build tour packages with visual itinerary builder; assign agents.
  • Document Approval Workflow: Review uploads with preview modals; approve/reject with feedback; track timestamps and agent attribution.
  • Analytics & Communication: KPI dashboard (conversion rates, approval times, onboarding velocity); real-time messaging with clients; searchable audit logs.
  • System Configuration: Manage checklist templates, testimonial display, admin roles, and session timeout settings.

Database Layer (18 Core Tables)

MySQL 10.4+ relational database organized into functional groups: User Management (admin_accounts, clients), Package Management (tour_packages, client_itinerary), Documents & Media (uploaded_files, client_trip_photos, client_reviews), Communication (messages, threads, notifications), Onboarding & Feedback (checklist_templates, client_checklist_progress, user_survey_status, feedback), and Compliance & Analytics (audit_logs, system_logs, photo_tags). Features proper indexing, foreign key relationships, and JSON columns for complex data structures.

Key Architectural Strengths: Modular processing layer for scalability; WebSocket integration with polling fallback for real-time communication; role-based access control with prepared statements for security; procedural PHP with 100+ reusable components for maintainability; complete audit logging for compliance.

4.2 Core Components

Client Layer (User Facing)

  • client/login.php: Access code-based authentication (e.g., JVBT-1234) for secure client entry
  • client/client_dashboard.php: Personalized view with assigned package, trip status, checklist progress, quick actions
  • client/upload_document_client.php: Multi-document upload interface with drag-drop, progress tracking, approval status
  • client/view_assigned_package.php: Detailed itinerary display with package info, day-by-day activities, confirmation toggle
  • client/messages_client.php: Real-time chat with assigned travel agent, message history, unread indicators
  • client/view_client_itinerary.php: Confirmation-specific itinerary view with dependency tracking
  • client/view_document.php: Document preview and status tracking (Pending/Approved/Rejected)

Admin Layer (Agent Facing)

  • admin/admin_login.php: Username/password authentication with configurable session timeouts per role
  • admin/admin_dashboard.php: Client overview table, KPI metrics (total clients, completed trips, conversion rates), pending items modal
  • admin/view_client.php: Comprehensive client profile with tabs: overview, documents, itinerary, trip photos, testimonials, audit history
  • admin/admin_tour_packages.php: Package management: create/edit/archive packages with day-by-day itinerary builder
  • admin/messages.php: Client list sidebar for messaging selection with chat thread history and read/unread tracking
  • admin/audit.php: Searchable, filterable audit log with action type, severity, KPI impact, change details as JSON
  • admin/admin_testimonials.php: Client review management with display toggle and rating filters
  • admin/admin_settings.php: System configuration, session timeout settings, admin user management

Processing Layer (Backend Logic)

  • actions/db.php: Centralized database connection with environment-aware error handling (development vs. production modes)
  • includes/auth.php: Guard function for session validation, role-based access control, dynamic session timeout management
  • actions/process_*.php: 60+ form handlers for: client creation, document upload/approval, status updates, checklist progression, surveys, messaging
  • includes/log_helper.php: Audit logging with complete context: actor ID/role, session ID, IP, timestamp, changes as JSON, severity, business impact
  • actions/notify.php: Notification manager for event dispatch (document approval, status change, message received, checklist completion)
  • websocket_server.php: Ratchet-based WebSocket server for real-time bidirectional messaging with polling fallback for compatibility
  • includes/image_compression_helper.php: Auto compression for all uploads (documents and trip photos) with MIME detection and JPG normalization

Data Persistence & Support Components

  • Database Tables (18 core): User management, package/itinerary tracking, document uploads, messaging, notifications, checklist progress, surveys, feedback, compliance audit logs, photo metadata
  • File Storage: uploads/client_profiles/, uploads/client_{id}/, uploads/admin_photo/ with automatic compression and unique naming (entity_timestamp_random.jpg)
  • Session Management: Server-side session files with dynamic timeout enforcement fetched from admin_accounts per admin
  • Components (100+ PHP templates): Reusable UI components in /components folder: modals, forms, tables, cards, status alerts, survey modals, document viewers
  • JavaScript Utilities: Vanilla JS + Alpine.js for interactivity; WebSocket client, message polling, notifications, form validation without heavy frameworks

4.3 Key Architectural Decisions

  • Procedural PHP: Chosen for simplicity, rapid development, and minimal learning curve for team
  • No Frontend Frameworks: Vanilla JavaScript + Alpine.js reduces dependencies and keeps bundle size small
  • JSON in Database: MySQL JSON columns allow flexible schema for itineraries, checklists, notifications without complex normalization
  • WebSocket with Polling Fallback: Real-time messaging for modern browsers; graceful degradation for shared hosting
  • Centralized Auth Guard: Single source of truth for permission checking across all protected pages
  • Comprehensive Audit Logging: Every action tracked with full context for compliance and analytics

5. Input-Process-Output (IPO) Design Model

5.1 IPO Diagram

5.2 Detailed IPO Breakdown

A. INPUT

Definition: All data sources feeding into the system from users and external systems.

Client Inputs:
  • Account Information: Registration via unique access code (e.g., JVBT-XXXX)
  • Documents: File uploads (passport, ID, visas, travel documents) with MIME type validation
  • Media: Trip photos uploaded day-by-day (images compressed to <3MB)
  • Survey Data: Structured responses to perception surveys (Likert scale 1-5, open-ended feedback)
  • Communication: Messages sent to assigned agent (text, optional attachments)
  • Actions: Itinerary confirmation, document review acknowledgments, checklist item completion
Admin Inputs:
  • Client Management: Add clients, assign packages, designate agents
  • Package Definition: Create tour packages with duration, origin/destination, itinerary day-by-day breakdown
  • Document Review: Approve/reject uploaded documents with optional feedback comments
  • Status Overrides: Manual status updates if auto-update logic needs adjustment
  • Notifications: Manual notification sending for special events
  • Communication: Messages to clients, broadcast notifications to admins

B. PROCESS

Definition: Business logic and computational steps that transform inputs into outputs.

Authentication & Authorization:
  • Guard function validates session for every protected page
  • Role-based access control (Superadmin → Admin → Read-Only, Client)
  • Session timeout checks with dynamic timeout per admin (fetched from DB)
Document Processing:
  • MIME type detection and validation
  • File size validation (max 3MB)
  • Image compression and format normalization to JPG
  • Secure file storage with unique naming (client_{timestamp}_{random}.jpg)
  • Database record creation with status=Pending
Status Auto-Update Logic:
  • Evaluate client based on:
    • Document uploads/approvals (Awaiting Docs → Under Review → Confirmed)
    • Trip date ranges (Confirmed → Trip Ongoing → Trip Completed)
    • Manual overrides (by admin)
  • Trigger status-change audit log entry with actor and timestamp
Notification Dispatch:
  • Trigger on: document approval, status change, message received, photo approved
  • Insert notification record with event_type, recipient, message, action_url
  • Broadcast via WebSocket if connected; fallback to polling
  • Update last_activity timestamp for session tracking
Real-Time Messaging:
  • Client sends message → POST to actions/send_message.php
  • Message validated and stored in messages table with thread_id
  • WebSocket broadcasts to subscribed clients in thread channel
  • Read/unread status tracked; history retrieved on page load
Audit Logging:
  • Every action logged with:
    • Actor context (ID, role, session_id, IP, user_agent)
    • Change data (old → new values as JSON)
    • Severity and business impact classification
Survey Processing:
  • Trigger survey modal on first login or trip completion
  • Collect user responses with timestamps
  • Store response_payload as JSON in user_survey_status table
  • Mark is_completed=1 after submission

C. OUTPUT

Definition: Data and visualizations delivered back to users after processing.

Client Outputs:
  • Dashboard: Personalized view with assigned package, trip dates, documents status, itinerary preview
  • Status Updates: Real-time notifications showing document approvals, status changes, agent messages
  • Checklist Progress: Visual progress bar with completed/pending items and points earned
  • Itinerary View: Day-by-day activities with optional confirmation button
  • Photo Gallery: Upload interface during/after trip; gallery view of approved photos
  • Message Thread: Chat history with assigned agent, new message alerts
  • Survey Modal: First-login and post-trip survey forms with feedback collection
Admin Outputs:
  • Client Dashboard: Sortable/filterable table of all clients with status badges, quick stats
  • KPI Metrics:
    • Total clients, confirmed bookings, completed trips
    • Conversion rate (% reaching trip completion)
    • Onboarding velocity (average days to first document)
  • Client Detail View: Tabs for profile, itinerary, documents, trip photos with approval workflows
  • Document Management: Documents table with preview modals, approval/rejection controls, comments
  • Analytics Charts: Document status pie chart, approval time bar graph, conversion funnel
  • Audit Log: Searchable table of all actions with filters (user, action type, date range, severity)
  • Messaging Interface: Client list for selection, chat thread with full message history
  • Export Reports: Audit logs, client lists, KPI summaries as downloadable files
System Outputs (Implicit):
  • Database Records: Persistent storage of all inputs for audit and historical analysis
  • Log Files: Error logs, access logs, WebSocket activity logs
  • Email Notifications: (Future feature) Confirmation emails, approval notifications, reminders

7.3 Risk Mitigation & Contingencies

Key Risks & Mitigation Strategies:

Risk: Critical bugs found during beta testing
Mitigation: Dedicate Weeks 7-8 for fixes; escalate critical issues to priority status with daily stand-ups. If major bugs are found in Week 6, extend bug-fix phase by 1 week (push deployment to Week 11).

Risk: Low pilot adoption / tech reluctance
Mitigation: Schedule 1-on-1 onboarding calls with pilot clients; provide dedicated support phone line during beta; offer incentive (discount on next trip).

Risk: WebSocket server instability under load
Mitigation: Load test with 50 concurrent connections in Week 2; have fallback polling ready; monitor connections 24/7 during launch.

Risk: Database performance degradation with real data volume
Mitigation: Create database indexes during Week 1; test with 10,000+ mock records in staging; monitor query performance daily during Weeks 10-13.

Risk: Admin staff not fully trained by launch
Mitigation: Provide recorded training videos; send out checklists & quick-reference cards 2 weeks pre-launch; schedule 1-on-1 refresher calls 3 days before go-live.
